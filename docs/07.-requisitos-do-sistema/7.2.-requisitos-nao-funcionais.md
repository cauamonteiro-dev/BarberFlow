# 7.2. Requisitos não Funcionais

| ID | Requisito | Evidência ou limite |
| --- | --- | --- |
| RNF01 | Utilizar SGBD relacional | PostgreSQL, SQL e mapeamento JPA. |
| RNF02 | Manter integridade referencial | PK, FK, unicidade, NOT NULL e CHECK, complementados pela API. |
| RNF03 | Persistir os dados | Dados permanecem no PostgreSQL após reinício do serviço; sujeitos ao ciclo de vida da hospedagem. |
| RNF04 | Integrar pela API | O navegador não acessa diretamente o banco nem recebe sua senha. |
| RNF05 | Oferecer interface compreensível | Identificação da unidade, campos rotulados, mensagens e navegação por perfil. |
| RNF06 | Facilitar manutenção | Componentes React, camadas Java, migrações versionadas e testes. |
| RNF07 | Impedir estados incompatíveis | Validação transacional de recursos, vínculos e conflitos. |
| RNF08 | Funcionar em celulares | Layout responsivo, tabelas adaptadas e menu administrativo com rolagem. |
| RNF09 | Oferecer temas claro e escuro | Preferência do sistema, escolha persistida e sincronização entre abas. |
| RNF10 | Proteger sessão e escrita | BCrypt, cookie HttpOnly/SameSite, Secure na nuvem e CSRF nas mutações. |
| RNF11 | Autorizar por recurso | Verificação no backend, inclusive IDs e filtros de outras unidades. |
| RNF12 | Evitar reserva concorrente | Validação e gravação na mesma transação com bloqueio da unidade. |
| RNF13 | Permitir reprodução | Inicializador integrado, Maven Wrapper, build e validação no GitHub Actions. |
| RNF14 | Dar retorno durante consultas | Estado de carregamento, falha recuperável e descarte de respostas substituídas. |
| RNF15 | Apoiar acessibilidade básica | Foco, rótulos, estados textuais e respeito à preferência por movimento reduzido. |

Não foi realizada certificação integral de acessibilidade, auditoria independente de segurança ou teste de capacidade para grande volume de usuários. A otimização da consulta diária reduz acessos repetidos ao banco, mas não estabelece um tempo de resposta garantido em hospedagem gratuita.
