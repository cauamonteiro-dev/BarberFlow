# 08. Regras de negócio

## Relacionamentos e catálogo

| ID | Regra |
| --- | --- |
| RN01 | Um cliente pode estar vinculado a várias barbearias. |
| RN02 | O par cliente–barbearia é único; reativar utiliza o mesmo vínculo. |
| RN03 | Cada barbeiro pertence a uma barbearia. |
| RN04 | Cada serviço pertence a uma barbearia. |
| RN05 | A reserva relaciona unidade, cliente, profissional e serviço. |
| RN06 | Uma reserva exige vínculo do cliente com a unidade; a primeira reserva pelo portal cria o vínculo ausente, sem reativar um vínculo bloqueado. |
| RN07 | Reservas do mesmo profissional não podem se sobrepor; intervalos adjacentes são aceitos e cancelados liberam o horário. |
| RN08 | Serviço exige nome, preço não negativo e duração positiva; a API limita a duração a 1.440 minutos. |
| RN09 | Cada plano pertence a uma unidade. |
| RN10 | Cada assinatura relaciona cliente e plano. |
| RN11 | A assinatura exige vínculo com a unidade do plano. |
| RN12 | Inativar catálogo ou vínculo preserva os registros; novos usos exigem os recursos correspondentes ativos. |
| RN13 | Situações da reserva: AGENDADO, CONFIRMADO, CONCLUIDO e CANCELADO. |

## Acesso, agenda e histórico

| ID | Regra |
| --- | --- |
| RN14 | O administrador geral possui autorização global explícita; a Barbearia acessa somente sua unidade. |
| RN15 | O cliente da reserva é derivado da sessão; informar outro identificador não permite assumir outra pessoa. |
| RN16 | O barbeiro consulta e atende somente reservas atribuídas ao profissional vinculado à conta. |
| RN17 | O cadastro público cria cliente e conta sem conceder funções administrativas; e-mail coincidente não permite apropriar cadastro anterior. |
| RN18 | Somente o administrador geral concede/remove gestão Barbearia; não se remove o último gestor local. |
| RN19 | A reserva deve caber integralmente em uma faixa semanal e não intersectar bloqueios. Pausas usam faixas separadas. |
| RN20 | Expedientes têm dias 1–7 (segunda–domingo), fim posterior ao início e nenhuma sobreposição; bloqueios e redução de expediente não podem invalidar reservas futuras em aberto. |
| RN21 | O cliente cria, remarca ou cancela somente reservas próprias futuras em aberto; não reabre reservas canceladas ou concluídas. |
| RN22 | A consulta do portal oferece inícios a cada 15 minutos, de hoje até um ano à frente; exclui horários já passados. A disponibilidade é revalidada ao salvar. |
| RN23 | O barbeiro só conclui um atendimento após seu início; não modifica os já cancelados ou concluídos. |
| RN24 | A conclusão é definitiva e registra `concluido_em`; registros concluídos não são alterados ou reabertos. |
| RN25 | O valor combinado é registrado na reserva; trocar o preço do catálogo não o altera. Trocar o serviço registra o novo preço; remarcar o mesmo serviço preserva o valor. |
| RN26 | No portal, preço exibido divergente do preço atual impede nova reserva ou troca de serviço até revisão do valor. |
| RN27 | Faturamento soma valores de CONCLUIDOS; AGENDADOS/CONFIRMADOS compõem valor em aberto. Nenhum deles comprova pagamento recebido. |
| RN28 | Históricos migrados sem preço exato são identificados como estimados; sua conclusão pode usar o término original como aproximação. |
| RN29 | Assinatura vigente: situação ATIVA, início até hoje e fim ausente ou a partir de hoje; não há cobrança, renovação automática ou consumo de cotas. |
| RN30 | Recursos existentes não mudam de unidade por alteração de identificadores; compatibilidade e autorização são verificadas na API. |

A gestão administrativa pode cadastrar históricos. As restrições de data futura do autoatendimento não devem ser generalizadas para todos os formulários administrativos. Reservas canceladas podem ser reabertas pela gestão após validação; o portal do cliente não oferece essa possibilidade.

Alterar somente a situação preserva a duração originalmente reservada. A serialização das gravações usa bloqueio da linha da barbearia: validação e inserção compartilham a mesma transação. Gravações SQL externas precisam aplicar regras equivalentes; o banco não possui uma restrição de exclusão que, sozinha, implemente todo o controle de agenda.
